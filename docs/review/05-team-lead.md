Reviewer persona: head of a large estimating team running several projects at once. Reviewed 2026-11-23 on
`main` at `3868013`, local Docker stack, account `lead@review.test` (org `lead-co`, Team plan).

**What I did, hands-on.** I invited six teammates through the UI: two estimators, a library editor, an
approver, a viewer and an org admin. Each one accepted from the MailHog link in their own Playwright context
and set a password. I created three projects: *Team Tower* (S05 Duplex, then

estimators co-edited one BoQ. I switched on approval with four-eyes, then ran submit → approve → save →
confirm → reopen twice. I published two versions of an org rule set and an org dictionary, promoted a
decision, removed a member, and read the org and project audit (UI and CSV).

Scripts and their outputs are in `docs/review/_scratch/lead/` (`s01…s25*.mjs`, `org-audit.csv`, `s11-out.json`).

## 1. Verdict

For one project team, boqlet already changes the work. Re-measuring and diffing a model revision dropped
from hours to minutes: v2 uploaded, parsed, regenerated and compared against saved version A in under 15 s.
Co-editing is live, four-eyes is enforced on the server, and every number can be traced. For a 20–30
person department, though, the weak point is **consistency across people and projects**. Org library
changes never reach existing projects. Answers are kept per project, so two estimators can and did produce
different BoQs from the same model on the same day. A promoted answer can be silently dropped by the next
library publish. With approval switched on, an estimator can still send an unreviewed working version to a
client by public link. Oversight is also thin. There is no team view, "Needs you" is personal, the audit
leaves out the values that changed, and the library editor cannot see where their presets are used. Prices
are "on request" and every viewer or approver takes a seat, so the subscription can't yet be justified for
a team this size. **Recommendation: pilot it with one team on one project type now. Don't roll it out to
the whole department until the High findings LEAD-001 to LEAD-004 are fixed.**

Assumptions: a design-led firm, Revit or Archicad models of decent quality, and the firm's library already
set up. Setting up the library is a one-off of 1–3 days for the standards lead and is not included below.
"Today" means a manual or semi-manual take-off: drawings and model schedules into Excel, or a
CostX-style tool, done by one experienced estimator. Measured figures from this session: Duplex parse
5–6 s, run 3 s, regenerate on v2 3 s, change report under 15 s. Baseline: S07 (13.6 MB Revit) parse
65–95 s with 67 questions (61 blocking); S06 (18 MB MEP) about 9 min. Time spent answering is my estimate,
at about 30–60 s per question with bulk answering on names.

**Department level (20–30 estimators).** Suppose each estimator handles about 1 first BoQ and 3 revisions a
month on medium projects. Today that is roughly 7.5 + 3 × 2.25 ≈ 14 person-days per estimator per month.
With boqlet it would be about 2.75 + 3 × 0.45 ≈ 4 days, plus about 0.5 day of overhead, so roughly
**9 person-days saved per estimator per month, or about 180–270 person-days a month for the department.**

That figure holds only if the models are good and the output is trusted, and FM-83 and LEAD-016 say trust
has not been earned yet. Until it is, I would halve the saving on first BoQs (reviewers will re-check
every quantity). The revision saving is the more robust figure, because the change report is concrete and
checkable.

## 5. Assumptions and judgement calls

1. **Hybrid method.** I used the UI for everything a person would see: invitations, accepting, project
   creation and upload, the BoQ dialog, settings, co-editing, review, changes, library, dashboards and the
   public page. Bulk steps where the UI adds nothing ran through the same signed-in sessions via the API:
   answering 10 questions, publishing presets, creating House A and B, the approval transitions. I reused
   each person's browser cookie, so these are the same sessions, not extra sign-ins.
2. **Seventh person.** I invited a seventh person (`lead-admin@review.test`, org admin) beyond the four
   suggested names, to test whether admins act as leads (LEAD-009).
3. **Lost invitation.** The first batch-invite script lost the viewer invitation. Re-sending it through the
   UI worked. I put that down to my script's timing and did not report it.
4. **Org setup.** `lead-co` had its setup marked done by the review setup script (`make-account.mjs`), not
   by the wizard. So the wizard (FM-62–64) is not judged here, and the org had no presets before mine.
5. **Library preset docs.** I built the org preset documents by hand, as a library editor's draft would
   be. My first dictionary entry used the wrong shape and was refused by the check. I fixed it before
   publishing, which does not affect LEAD-001: the lost entry was the promoted one, and the draft was
   valid.
6. **House A vs House B.** I deliberately answered two names differently to show what can happen. The
   point of LEAD-003 is that nothing stops or flags it, not that estimators would usually disagree.
7. **Ruled out.** An undo race in co-editing looked possible from the server code (whole-override
   replace, `Adjustments.java:291`). I dropped it after reading `edits.ts:210-226`: the client stops
   undoing lines someone else saved.
8. **Severity.** I rated severity from a department head's view: High means it undermines consistency or
   QA across the team, not that the app crashes. LEAD-004 is High because it defeats a control the firm
   switched on deliberately.
9. **Time estimates.** These are judgement, from typical take-off rates and this session's measured
   machine times, not from a timed user study. Times for answering and checking are assumptions, stated in
   the table.
10. **Shared stack.** The shared worker was busy with other reviewers' jobs at times (the House A parse
    waited about 150 s in the queue). I did not count queue waits as product slowness.
11. **Changes made.** I changed only my own org (`lead-co`): turned on approval and four-eyes, removed
    `lead-est2` at the end, and created share links on Team Tower. I touched no other account.
