`3868013`, on the shared local stack (`next dev` on :3000, Java on :8080). Method: Playwright 1.65 driving Chromium

## 1. Verdict

boqlet is visually coherent and has clear intent. The "precise instrument on paper" language is applied with
discipline: one typeface, hairline rules, purple only for the next action or for where you are. It is also
**unusually accessible for a v1**: across 80 axe scans there were **0 critical and 1 serious** violations, and the
sheet is a real `treegrid` with arrow-key, F2, Space and Ctrl+A editing. The weak points are where power users and
first-time users meet the dense screens:

- **The BoQ sheet spends 60–65 % of a 1440×900 viewport on chrome before its first row.** With the default 3D panel
  on, it also **hides the Source column, so the TO CONFIRM, DERIVED and MANUAL tags disappear**.
- **The setup wizard shows a first-time user raw formula editors.**
- **Every visit to a BoQ silently moves keyboard focus onto "Generate again".**

The viewer's colours and its dark-mode toolbar break the design guidelines outright. None of this needs a redesign:
most fixes are layout and default-state changes to components that already exist.

## 5. Assumptions and judgement calls

1. **Dev-server compile time is not counted.** First loads of many routes took 10–40 s (`crawl1.log`); I waited 6–12 s after `domcontentloaded` and re-shot pages caught mid-load (Exports, Project settings; `26b-`, `32b-`). The loading-skeleton screenshots (`21-boq-questions.png`, `26-boq-exports.png`, blank `32-project-settings.png`) are therefore not findings. The one exception is the axe `page-has-heading-one` / `landmark-one-main` on `32-project-settings`, which reflects the loading state.
2. **"Big BoQ"**: S08 (4,150 elements) generates **40 lines** (the engine aggregates by type), so the virtualised sheet was not stressed by row count. I judged sheet density on what the user sees per viewport, and stressed the large-element paths instead: line detail with many elements (`106b-…`, 5,984 px page) and the Log (10k px). I did not upload S07 or a second large file, to respect the shared one-job engine.
3. **Severity of UX-001 and UX-002 is high**, not critical: data isn't lost, but UX-001 hides status the product promises to show, and UX-002 can start an unintended run (with a cost on capped plans).
4. **UX-005 (viewer colours) is high** because the guidelines name "no green" explicitly and the viewer is on by default next to the sheet. In a pure WCAG sense it is not a violation.
5. **Axe "best-practice" rules were included** (landmarks, heading order, region); I report them as moderate or low and keep them separate from WCAG failures. Only `scrollable-region-focusable` maps to WCAG 2.1.1 / 2.1.3.
6. **Dark mode** was emulated with Playwright `colorScheme: "dark"` (theme "system"). I did not toggle the in-app theme button.
7. **Admin console not reviewed** (FM-69): the shared `pm-admin` account was in use, and the brief says to prefer skipping over taking over a session.
8. **Mobile (390)** is out of v1 scope (nfr.md), so UX-043 is low; I still report it because emailed links get opened on phones.
9. Created on the shared stack (my own data only): project "UX big structure" in `ux-firm` (S14, S13, S08 uploads, BoQ "Structure BoQ"); one share link on "Duplex quantities" (30 days); a new account `ux-new@review.test` with org "UX Newcomer Studio" (Free plan, wizard published with suggested answers). I edited no lines and answered no questions on the Duplex BoQ.
10. The `title=` count (155) and checkbox counts come from `grep` over `apps/app/src` and `apps/app/app`. They include some legitimate `title` uses, such as long names, so read them as orders of magnitude.
11. Where the design guidelines and the product disagree, I treated the **guidelines as the intended spec** (they say they override design-system.md and were confirmed by the owner). Where the guidelines themselves look stale or untracked, I logged a `spec-issue` (UX-034, UX-045, UX-047, UX-048).
12. A screenshot of a dialog in full-page mode shows the overlay covering only the viewport (`101-generate-dialog.png`). That is a Playwright full-page artefact, not a product bug, and is not reported.
