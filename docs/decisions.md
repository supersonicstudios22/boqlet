## Engine and platform decisions (D01–D75)

Oldest first within each theme. Status is one of:
**Active**, **Revised** (still holds, with changes noted), **Superseded** (replaced; kept so
nobody re-proposes it without knowing why it changed), **Open** (direction agreed, details not).

Sources: two earlier planning chats (1 Aug and 9 Sep 2026) and the main conversation
(3-9 Oct 2026, `docs/archive/reference/conversation/`). Where a later decision changed an earlier one, the
later one wins.

### Product and scope

| ID | Date | Decision | Why | Status |
|---|---|---|---|---|
| D01 | Aug 2026 | Input is **IFC only**. No native Revit/Archicad files, no other BIM formats. | IFC is the open ISO standard every tool exports; one parser, no vendor SDKs. | Active |
| D02 | Aug 2026 | The output must be **flexible**: users can play with, change and select data in the result, not just download a fixed report. | Professionals adjust BoQs; the value is in control, not a black box. | Active |
| D03 | Aug 2026 | Users choose from **presets** (rules, classifications, dictionaries) or create and edit their own. | Every market, client and firm measures differently. | Active |
| D04 | Oct 2026 | The product is **international**. No country's standard is the default; regional practices are examples, not the target. | Owner instruction ("do not focus on Bosnian/Serbian/Croatian, it was an example"). | Active |
| D05 | Oct 2026 | The engine **cannot calculate what is not in the model**. It derives proxies where possible, flags the rest, and moves on; the user may supply the information or not. | Agreed realistic expectation; magic is not a requirement. | Active |
| D06 | Oct 2026 | Four quantity sources: **measured, derived, manual, flagged**. Nothing is silently dropped. | A silently missing line is the worst possible outcome in a BoQ. | Active |
| D07 | Oct 2026 | Output is a **draft for professional approval**, never a certified BoQ. | Liability sits with the qualified person who signs it. | Active |

### Engine design

| ID | Date | Decision | Why | Status |
|---|---|---|---|---|
| D10 | Aug 2026 | A **Python** step turns raw IFC into a unified JSON holding everything later steps need. | ifcopenshell (the mature IFC library) is Python. | Active, now `ParsedModel` (D16) |
| D11 | Aug 2026 | **Rules are data**, interpreted by a generic engine. v1 = parameterised templates (fixed structures, editable values); v2 = full rule builder. The data model must allow v2 without a rewrite. | New standards must not need code changes. | Revised by D13-D15: the rule type already supports formulas, so the v2 builder is a UI question, not a data-model change |
| D12 | Sep 2026 | Classification is a prerequisite step and **measurement rule sets are keyed by classification codes**, so a rule set targets one classification system. | Seemed natural at the time. | **Superseded** by D14. Rules now select elements by IFC class, dictionary terms and properties; classification labels lines afterwards. A rule set works with any code list, and any number of code lists apply at once. |
| D13 | Oct 2026 | The engine **measures every element once** into a rich set of primitives (`MeasuredElement`); rules only select, combine and label those primitives. Rules contain no measuring logic. | Lets any rule set, from any source, run on the same measurements; makes re-runs cheap. | Active |
| D14 | Oct 2026 | Four independent inputs plus decisions: `getBoq(models, rules, classifications, dictionaries, decisions)`. **Rules change numbers; classification never does.** Classification is a list (zero, one or many systems). | Separates "how to measure" from "how to label"; lets the same quantities pivot into any code structure. | Active |
| D15 | Oct 2026 | One universal rule type (`OurRuleType`) with **slots**: number, choice, boolean, text. Structural differences between standards via `choose` and `when`; `formula` as the safety valve. Rule sets **extend** a base and state only differences (`RuleSetPatch`), flattened at run time; the flattened snapshot is stored with the result. | Standards differ in values and in choices of method; both fit one shape. Any standard becomes a filled-in copy. | Active |
| D16 | Oct 2026 | Two data layers: **ParsedModel** (faithful snapshot of one IFC, no decisions, expensive, cached per file hash) and **MeasuredElement** (dictionary applied, quantities adopted, cheap to recompute). | The parsed model stays reusable when dictionaries or engine logic change. | Active |
| D17 | Oct 2026 | Dictionaries turn raw names into **canonical terms with a hierarchy** (`concrete.in_situ` under `concrete`). Rules match on terms (`material under "concrete"`), not raw names. Layers: project, company, global; most specific wins. | One rule set works on any model in any language. | Active |
| D18 | Oct 2026 | **Decisions** are every answer a user gave (names, missing data, unmatched elements, codes). They are a project-level patch layer beside inputs 1-4, never written into the IFC, the company rule set or an official code list. Name answers can be **promoted** to the company dictionary (a permission). | You do not edit the architect's model or the company standard because of one project. | Active |
| D19 | Oct 2026 | **Question ids are deterministic**, built from content (`name:{field}:{raw}`, `missing:{rule}:{guid}`, `unmatched:{class}:{type}`, `unclassified:{system}:{lineKey}`), so stored decisions re-apply on every run and model version. | The user must never answer the same question twice. | Active |
| D20 | Oct 2026 | Only **blocking** questions stop a BoQ from being complete. Informative ones (unmatched elements, unclassified lines with a default) do not. | A demo rule set that ignores most of the model must still produce a BoQ. | Active |
| D21 | Oct 2026 | **A safe expression language**, parsed to an AST and evaluated by the engine only. Never Python `eval`; never a second evaluator in the browser (preview goes through the engine). | Users write formulas; two evaluators drift apart. | Active |
| D22 | Oct 2026 | Rule language levels: **parameters** (slots) + **formulas**. Scripts as an escape hatch only if ever needed (security and support cost). | Parameters and formulas cover the vast majority of real rules. | Active (no scripts) |
| D23 | Oct 2026 | The engine **runs any rules but does not judge them**. It catches mechanical problems (integrity, missing fields, unmatched or double-claimed elements); whether a rule matches a standard is the author's responsibility. Shipped presets are examples, not the product. | Source-agnostic engine; the product is engine + rule language + editor. | Active |
| D24 | Oct 2026 | Adoption policy: trust **reported quantities** (IFC quantity sets, then authoring-tool sets) over geometry when both exist, log mismatches; wall area = volume / thickness; steel by nominal kg/m from the section name. | The Duplex showed reported values are join-aware while geometry double counts junctions; Revit wall Area was inconsistent with Volume. Details in docs/architecture/engine.md and 09. | Active (v0, revisit with more files); **revised by D71–D73** (unit errors; impossible or implausible reported areas and a slab's stated Width give way to the geometry) |
| D25 | Oct 2026 | Aggregates: measure the **parent** (roof, stair) and skip its parts by default; a rule can opt parts back in (`parts: "include"`, used for stair railings). | Avoids double counting while keeping railings measurable. | Active |
| D26 | Oct 2026 | Every line carries a **trace** (formula, parameter values, each element's share, source line for derived lines) and the run carries an ordered **calculation log**. | Professionals do not trust untraceable numbers; it is also how developers debug rules. | Active |
| D71 | 23 Nov 2026 | **Exporter unit errors**: a stated volume, area or length within 2 % of 10^±3 or 10^±6 times the closed mesh's value is taken as a unit error. The geometry's value is used, the `contradiction` question keeps its deterministic id (`contradiction:{volume\|area\|length}:{class}:{type}`), stays non-blocking and recommends (`suggestion`) the geometry, the element records `unit_scale`, and its lines carry a note. Answering "reported" keeps the stated value. | Review QS-001 / DEC-31: S09 (an IFC4 sample house) states every slab volume ×1000; adopting it priced the main slab at 68,714 m³. Only a closed mesh qualifies, so a broken mesh never overrides the file. Revises D24. | Active (review WP-A1, A-02) |
| D72 | 23 Nov 2026 | **Reported areas and slab thickness are checked against the geometry.** A net area larger than the gross area of the same quantity set is impossible and not used. A reported area more than the contradiction threshold away from a clear plate's measured sides raises `contradiction:area:{class}:{type}`; while unanswered the geometry is used when the stated value is outside 0.5–2× the geometry (implausible), else the stated value. A horizontal plate's stated thickness quantity (`Qto_*.Width`, not a layer set) that the thin axis contradicts gives way to the geometry while unanswered; a layer-set thickness is kept and asked as before. | Review QS-003 / DEC-31: Revit 2021 IFC4 writes a slab's whole surface as `NetArea` (S07 ×2.22, S08 ×2.54) and a pile cap's plan size as `Width` (3.8 m for a 1.0 m cap); both were adopted silently. A layer set is the designer's build-up, a `Width` quantity is an exporter's guess. Revises D24. | Active (review WP-A1, A-03) |
| D73 | 23 Nov 2026 | **Contradictions can block.** The thresholds are resolution settings: `contradictionWarnPct` (default 10) asks, `contradictionBlockPct` (default 50, never below the warn threshold, checked before a resolution preset is published) blocks: an element whose stated volume, area or thickness differs from the geometry by more than it makes its `contradiction` question blocking, unless the difference is an exporter unit error (D71). While unanswered, the geometry is used and recommended when the mesh is closed and the stated value is outside 0.5–2× the geometry (D72 for areas and a plate's stated Width); otherwise the stated value. Name-question blocking is unchanged (DEC-32). | Review QS-002 / DEC-31: every contradiction was optional with the stated value recommended, so a −95 % slab thickness never stopped "complete" while 61 name questions did. More runs end `needs_input`; that is the intent above 50 %. | Active (review WP-A1, A-04) |
| D74 | 23 Nov 2026 | **A line with a quantity can still be "to confirm".** `BoqLine.toConfirm` marks a line some of whose elements had no value (`measured` of `elements`) or whose quantity rests on an open `contradiction` question (any, blocking or not, unit errors included: the number is the engine's choice until a person answers). Derived lines and aggregates follow their sources; a person's quantity edit confirms the line. `stats.flaggedLines` counts them with the lines without a quantity (no new stats key); the line keeps its `source`. | Rule 5 and review QS-008: S09's external-wall line was 31 % short from 2 of 3 walls and read as complete in the sheet and the Excel. One count of "lines to look at" keeps the header, run history and Excel consistent. | Active (review WP-A2, A-05) |
| D75 | 23 Nov 2026 | **Plausibility warnings, not blocks.** The engine warns (`implausible`) when an element is probably not what its class says or a quantity is bigger than the building can hold: a slab thicker than it is wide or than 1.5 m, a slab whose name has a word such as pile, pad or cap, a floor-slab line above footprint × storeys, a storey's floor slabs above 3 × the footprint. Thresholds and the name words are resolution settings (`plausibility`); the default words are a multilingual list (international product), matched as whole words, not regular expressions. Warnings never change a number or the run status. | Review QS-013 / LEAD-016: topography and steel piles exported as slabs were priced as floors with no hint; a lead could not rely on "complete" meaning "plausible". Blocking would stop every Revit model with a pad. | Active (review WP-A2, A-07) |
| D76 | 23 Nov 2026 | **A wall is measured by its faces.** A wall's net area is the mean of its two measured faces (the parser cuts the openings before measuring them) when its mesh is a closed, clear plate standing up whose oriented box is at most 1.5x its thickness thick; volume / thickness is the cross-check (more than the contradiction threshold apart raises the existing thickness `contradiction`) and the fallback (curved or bent walls, open meshes, no sides). Prismatic walls give the same number either way; layer volumes stay layer area x layer thickness; an answer to a wall's thickness or volume contradiction changes its m3 and thickness-based quantities, no longer its m2 area. The Duplex party wall line moves from 71.67 to 78.83 m2 (`HAND_BOQ` re-derived from the IFC extrusions) | Review A-09 (QS-004, DEC-34): volume / thickness understated every wall whose body is not a full prism (Duplex party walls -9.1 %, S07 partitions -11 to -16 %), and with it every finish taken from the wall area |
| D77 | 23 Nov 2026 | **Formwork to footings is measured from the geometry.** A new measured field `vertical_face_area`: a footing's mesh faces standing up (sides and ends) less the part lying against or inside another closed footing, wall, slab, column, pile or beam (parse `verticalFaces`); without it, 2 x (length + width) x height. as-modelled's `formwork_footings_formula` defaults to it ("Vertical faces from the geometry"); the two box formulas stay choices. Duplex footing formwork 37.02 → 36.19 m2 (the outline of the seven strips' union x 0.3 m, by hand); S04 ring footing 3.72 → 15.15 m2. The parse format is not bumped: the field is optional and older parses fall back | Review A-10 (QS-005): 2 x length x height assumed a straight strip and left out the ends; formwork is on by default |
| D78 | 23 Nov 2026 | **Wall finishes are measured on the face that carries them, by the walls' opening rule.** as-modelled's `paint-walls` becomes an item (it was a derived rule over the plasterboard layers' area): every wall with a plasterboard layer, `breakdown: face`, each face whose outermost layer is plasterboard (`Face.layer_material`, from the layer set's order and direction), openings deducted by the walls' slots unless `finish_openings` is `own` (then `finish_opening_mode`, `finish_opening_threshold`, `finish_opening_compare_by`). The formula slot `paint_walls_formula` is removed. `partFilter` is applied after breakdown, as documented (an element is taken when one of its parts passes); a face shared between rooms deducts its share of the openings; a side's faces add up to the side. Duplex paint 717.51 → 712.68 m2 (exterior walls: inner face only); demo-tweaked paint now follows its kept openings (720.14 m2) | Review A-11 (QS-009, DEC-22): walls and finishes in one BoQ followed two different opening rules, and a one-sided finish took the wall's mean area |
| D79 | 24 Nov 2026 | **Reveals are finish work, counted once per face.** `addReveals` adds, per deducted opening and per face measured, `(2 x height + width) x depth / 2` (depth = the opening's, else the element's thickness; the frame is taken as central), so a wall finished on both faces adds each reveal's full depth once. as-modelled removes the wall slot `wall_add_reveals` (reveals are not structure) and offers `finish_add_reveals` (off by default) on `paint-walls`; `standard-style-example` turns it on. A firm's saved patch that set `wall_add_reveals` still runs, its value ignored. | QS-020, ENG-023 (review A-12, DEC-35): reveals added to the wall overstated structure, and `both` doubled them. The opening's own frame position is not in the IFC data the parser reads, so half the depth per face is the neutral default; a firm whose standard measures reveals differently writes its own deduction (the field stays on every deduction). |
| D80 | 24 Nov 2026 | **A slab's perimeter is measured as its outer edge and the edges of its openings, apart.** `perimeter_openings` = 2 x (width + height) of each opening through the element (plan size), `perimeter_outer` = the perimeter less that; a reported `Perimeter` is taken as the total (noted on the element). as-modelled's edge formwork defaults to both together, the number it gave before; "Outer edge only" is the other choice. | QS-023 (review A-13): the two choices did not do what they said (the first was not outer only, the second double counted the openings). The default keeps formwork to the edges of openings, which is formwork too, so no default quantity moves. |
| D81 | 24 Nov 2026 | **Shipped system presets are published to every database on deploy.** A repeatable Flyway migration (`R__Sync_system_presets`) publishes a new system version of each preset whose file changed, and of every preset built on it (its `extends` points at the parent's newest version); published versions never change. BoQs and org presets that pinned an older version keep it (the Library's newer-version badge, A-44, is how a firm moves); BoQs that use the system default take the new one on their next run, which the change report shows. | Found at the WP-A3 exit check: V5 seeded system presets once, so no preset change since v1 (A-10's footing formwork, A-11's paint, A-12, A-13) would ever reach booqlet.com or a local database that already existed; only fresh test databases saw them. |
| D82 | 24 Nov 2026 | **Slab concrete is the slab's in-situ concrete layers.** as-modelled's `slab-concrete` measures each layer under `concrete` except screed and precast (`slab_concrete_layers: in_situ`; `all_concrete` counts them too) as area x layer thickness; a slab of one layer counts its own volume; a slab without a layer set counts when its material is in-situ concrete. Concrete masonry units and concrete blocks are masonry in the seed dictionary. | CAS-017 (review A-14): the whole build-up of a layered floor (S09: screed, insulation, air, block, precast) was in-situ concrete when its thickest layer was concrete-like. Screed and precast are other trades and other items; the slot keeps a firm's convention. |
| D83 | 24 Nov 2026 | **A roof with its own closed body and no layer set is measured by its faces looking up.** Developed area = their true area, footprint = their plan projection, thickness = volume / area; geometry provenance. A roof with a layer set keeps volume / layer thickness; an aggregate roof keeps the sum of its parts. | CAS-018 (review A-15): S09's main roof, the model's largest roof item, was an empty flagged line. The up faces of a closed body are its weathering surface, pitched or flat, as the review's oracle (`up_true`) measures it. |
| D84 | 24 Nov 2026 | **Unclassified objects (proxies) are asked about, not billed, by default.** as-modelled's `include_proxies` is off; the rule's `whenDisabled: "ask"` leaves them to coverage, so each class and type is a non-blocking `unmatched` question (answer: measure with a rule, or leave out). A firm that bills proxies switches the slot on. A disabled rule without the field still excludes what it matches. | QS-014 (review A-16, DEC-36): "Honey Locust 8 nr" and "Fine China - Plate 8 nr" were BoQ lines, and real work (S03's sand bedding, a volume) became "1 nr". Excluding them silently would break rule 5 (nothing silently dropped). |
| D85 | 24 Nov 2026 | **A member's length is its cut length.** Revit's `PSet_Revit_Structural` "Cut Length" comes before `PSet_Revit_Dimensions.Length` in the length sources (IFC base quantities still come first); the measure log names the source. | QS-012 (review A-17): Revit's Length is the analytical length between nodes, 0.10 m longer than the W310X60 beam itself (+1.4 % mass); the cut length equals the body's extrusion. |
| D86 | 24 Nov 2026 | **Copies of one object in several models that disagree are asked about.** Same-GlobalId copies that differ in class, type or material, or in thickness, volume, area or length by more than the resolution settings' `contradictionWarnPct`, raise one `duplicate_conflict:{guid}` question showing every copy's values; it blocks when a quantity differs by more than `contradictionBlockPct`. The answer names the model whose copy is measured. Unanswered (and for copies that agree), the copy kept is the one with a body, then the one of the discipline that owns the object judged on every copy (a wall one copy calls load-bearing concrete is structure's), then the one its own model owns, then the first model. Aggregates compare names only (their quantities are their parts', which are compared under their own GlobalIds). | QS-006 (review A-18, DEC-37): F01 kept 16 differing copies (CL_W1 24.29 vs 45.25 m2, a slab 0.225 vs 0.45 m) without a question, and when both copies passed ownership the model order decided. |
| D87 | 24 Nov 2026 | **An unanswered overlap between models blocks.** `FederationSettings.overlapBlocking` (default true; the shipped preset sets it) makes `overlap` questions blocking, so the run stays `needs_input` until someone says which model provides the elements (or both); unanswered, both are still counted in the interim sheet. With the setting off they are informative, and the BoQ header lists open non-blocking federation questions (overlaps, differing copies) as "to check". No new run status. | ENG-020 (review A-19, DEC-37): "complete" could mean a discipline's slabs counted twice. |
| D88 | 24 Nov 2026 | **Two item rules measuring one element in the same family warn unless both say what they claim.** After the lines are made, an element in item lines of two or more rules whose units are of one family (count, length, area, volume, mass), where a pair of the rules does not both declare `claims`, gives a non-blocking `double_count` warning per family and set of rules, listing the elements (BR-13). Not a default claim (DEC-33): a wall, its paint and its formwork legitimately share an element, and declared claims already separate them; shared claims stay `double_claim` questions. | ENG-008 (review A-20): two catch-all item rules counted the same 228 elements twice with status complete and no warning. |
| D89 | 24 Nov 2026 | **Shipped classifications never use a real code as a catch-all, and a map rule can check its code against the model.** ACME: external walls by dictionary type, else IsExternal = true when the type is not internal; internal walls by type (partition, lining, party), else IsExternal = false; any other wall goes to Z.99 "To be classified". demo-trades: Masonry only for walls of a masonry material, others fall to 99 Other. Uniclass EF's single `EF_25_10 Walls` is right for every wall (unchanged). New `MapRule.expect`: a condition every line the rule codes should meet; a line that does not keeps the code and gets a `code_check` warning (the Duplex party wall: internal by type, IsExternal TRUE). No quantity changes (rule 6). | QS-007 (review A-21, DEC-10): S01, S07 and S09 external walls (IsExternal TRUE) were coded D.02 Internal walls, and every other wall fell to D.02 too. |
| D90 | 24 Nov 2026 | **A material breakdown gives each material its own volumes, as a layer breakdown does.** Each group's net and gross volume = the element's net and gross area x the group's thickness; an element of one material keeps its own volumes. A volume measured by layer or material whose parts differ from the element's volume by more than 2 % is logged (`log.quantity.parts_volume`, warning), not scaled: parts stay layer area x thickness (D76/DEC-87), so a notched wall's parts are a little over its solid. | ENG-004 (review A-24, DEC-96): every material group kept the element's whole gross volume, so the Duplex walls by material came to 1,094 m3 for 240 m3 of walls. |
| D91 | 24 Nov 2026 | **A missing value is asked once per rule and element; a result the database refuses is not retried.** With a breakdown, the parts of an element share one `missing:{rule}:{guid}` question (`occurrences` = the parts; the id format of D19 is kept) and its answer is used for each part without a value. The pipeline merges any repeated question id into the first. A run or parse whose result breaks a database constraint fails as `result_invalid` (`retryable: false`), since every attempt gives the same result; other ingest failures stay `ingestion_failed` (retryable). | ENG-003 (review A-25): a layer breakdown with `onMissing: ask` gave 50 duplicate ids on the Duplex; the COPY into `run_questions` failed, and the job was retried as if the server had had a hiccup. |
| D92 | 24 Nov 2026 | **An expression has size limits, and breaking one is a user error.** At most 10,000 characters, 64 levels of brackets, calls, NOT and minus signs, and 200 chained operators. The parser refuses beyond them with an `ExprError` naming the position, so the Library's check lists it like a syntax error (`/presets/check` answers 200 with `ok: false` and the problem); the worker maps any input error, a `RecursionError` included, to 422 (the API's `400 engine_input`), never 503. | ENG-013 (review A-27, DEC-97): 2,000 brackets raised `RecursionError`, which reached users as `503 engine_unavailable` and fired outage alerts. |
| D93 | 24 Nov 2026 | **One unit registry with dimensions; a line unit outside it, or of the wrong dimension, is refused.** `packages/types/src/units.ts` lists every line unit (id, dimension, factor from SI); codegen writes it to `engine/ifc_boq/data/units.json`, and the engine converts line values, reads name-hint lengths and checks presets from it. `presets.check` (and every run, as a `rule_set` warning) reports a quantity, derived or manual unit that is unknown or measures another dimension than its quantity kind (formula, derived and manual units: any registered unit). `minimum` is stated in the line's unit. Ids are language-neutral; the app shows each in the user's language. The schema still accepts any text, so a run of an older preset still reads. | ENG-010 (review A-28): `cm`, `l`, `mm2`, `in` and `g` converted by 1 (a rule author picking `cm` got a 100x error), `mm` on an area was x1000, and four unit tables disagreed. |
| D94 | 24 Nov 2026 | **A quantity typed as text in an imported Excel is read with the firm's number format, and an ambiguous one is refused.** The API sends the org's `numberFormat` with the `import_boq_edits` job; the importer reads text with it ("1,234" = 1234 where "," groups thousands, 1.234 where it is the decimal mark), refuses a thousands mark that does not group three digits or the wrong separator, and without a format refuses text that could be read both ways ("1,234", "1.234,5"). The refusal is a per-row problem in the review. Number cells are unchanged. | ENG-018, FM-114 (review A-30): every "," became "." so "1,234" pasted as text imported as 1.234, 1000x too small, as a valid edit. |
| D95 | 24 Nov 2026 | **The CLI measures what the worker measures, and no set is lost.** `parse_file` returns the ParsedModel as its JSON reads back, so every in-process caller (CLI, compare-baseline, tests) sees what the worker stores in `parsed.json`. Property and quantity sets without a name are kept as `#<step id>`, a name an element already has as `<name>#2`, listed in one `pset_renamed` parse check. The engine reads `presets/user/` only when `IFC_BOQ_USER_PRESETS` is set. | ENG-011, DEC-06 (review A-31): S12's 30 unnamed quantity sets crashed the CLI (a `None` key) and were silently dropped under `"null"` on the worker path; same-name sets overwrote each other; a developer's local Library saves changed what the CLI measured. |
| D96 | 24 Nov 2026 | **Property sets flattened into one are read back, and a material may come from a property.** A property set whose every property is named "[Set]Property" (Synchro's 4D export puts all of an ArchiCAD model's sets into `SynchroResourceProperty`) is split back into the sets it names (`pset_split` parse check); an ordinary set with one bracketed name is left alone. An element the IFC associates with no material takes it from the first property `data/material_sources.json` lists (ArchiCAD's "Building Material / Composite / Profile / Fill"), resolved by the dictionaries like any material. | VER-006 (review A-33): S10 resolved "0 of 0 distinct names", `complete` with no question, although each of its elements names its material and its Pset_*Common. |
| D97 | 25 Nov 2026 | **Regular expressions a firm writes run on RE2, and unsaved dictionaries need the right to edit presets.** Dictionary `regex` entries, extractors and `matches` selectors are compiled by `engine/ifc_boq/user_regex.py` with RE2 (`google-re2`): matching is linear in the name; look-arounds, back-references and patterns over 500 characters are refused by the preset check and fail a run with the entry's id (an engine input error, not an outage); `` written next to a letter outside ASCII is refused too, since RE2's word boundaries are ASCII and such a pattern can never match (write `\pL`). Named groups keep both spellings. The names preview takes `draftDictionaries` only from an org library editor or a lead or estimator of the model's project (`ProjectAccess.presetEditor`, 403 otherwise); with saved dictionaries it stays open to every project role, and P54 Q43's preview of a saved draft is unchanged.
